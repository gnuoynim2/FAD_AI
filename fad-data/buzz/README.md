# 트렌드 대체 지표 일일 수집기

틱톡·인스타그램 수치는 공식 API로 받을 수 없어서, **공식 API로 받을 수 있는 데이터로 입소문을 재는 대체 지표**를 매일 쌓는다.
이 지표들은 과거 기록을 다시 받을 수 없으므로 **오늘부터 하루도 빠짐없이** 모아야 발표 때 쓸 기록이 생긴다.

## 모으는 지표 (키워드마다, 기준일 = 어제)
| 열 | 뜻 | 출처 |
|---|---|---|
| `blog_new` | 어제 새로 올라온 블로그 글 수 | 블로그 검색 (글 날짜로 셈) |
| `cafe_new` | 전날보다 늘어난 카페 글 수 (둘째 날부터) | 카페 검색 (글 날짜가 없어서 전체 수의 차이로 계산) |
| `news_new` | 어제 나온 뉴스 기사 수 | 뉴스 검색 |
| `buy_q` / `soldout` / `review` | 어제 블로그 글 중 구매처 질문 / 품절·재입고·웨이팅 / 구매 후기 표현이 있는 글 수 | 임시 규칙. 나중에 텍스트 분류 모델로 교체 |
| `*_total` | 그 키워드의 전체 검색 결과 수 | |
| `shop_total` | 등록된 쇼핑 상품 수 (선택) | 네이버 개발자센터 쇼핑 검색. NAVER API HUB에는 쇼핑 검색이 없음 |
| `*_capped` | 1이면 최신 글 1,000개 안에 어제 글이 다 안 들어가 **실제보다 적게 셈** | 검색 API는 1,000번째 결과까지만 줌 |

`output/posts/날짜.jsonl`에는 그날 블로그 글 제목·요약·링크를 저장한다. 나중에 팀이 "구매 의도 / 후기 / 품절 / 단순 언급" 정답을 붙여 **텍스트 분류 모델 학습 데이터**로 쓴다.

## 준비
```bash
pip install -r requirements.txt
```
1. `.env.example`을 복사해 `.env`를 만들고 NAVER API HUB 키를 넣는다. (`.env`는 절대 GitHub에 올리지 않음)
2. `watchlist.txt`에 지켜볼 키워드를 넣는다. `키워드 | 분야` 형식. **뜬 것, 이미 진 것, 아직 모르는 것을 섞는다.** 나중에 "뜰 것"과 "말 것"을 구분하는 학습에 둘 다 필요하다.

## 실행
```bash
python collect_buzz.py --limit 3      # 처음엔 3개만 시험
python collect_buzz.py                # 어제 기준 전체
python collect_buzz.py --date 2026-11-23   # 놓친 날 채우기 (최근 글 1,000개 안에 있을 때만 정확)
```
- 이미 모은 날짜·키워드는 건너뛰므로 여러 번 실행해도 된다. 중간에 끊겨도 다시 실행하면 이어서 모은다.
- 하루 호출 한도(검색 API 하루 25,000회)를 넘으면 멈추고, 다음 날 이어서 모은다.

## 호출 수 계산
키워드 하나에 블로그·뉴스 각 1~10회(어제 글이 많을수록 늘어남) + 카페 1회 → **보통 3~21회**.
키워드 300개면 하루 최대 약 6,300회라 한도 안에 들어간다.

## 매일 자동으로 돌리기
하루라도 빠지면 그날 기록은 나중에 정확히 복구하기 어렵다. 항상 켜져 있는 곳에서 돌리는 게 좋다.

**AWS EC2 (권장) — 설치 스크립트 사용**

1. 내 컴퓨터(Windows PowerShell)에서 buzz 폴더를 서버로 복사한다. `.env`는 복사하지 않고 서버에서 새로 만든다.
   ```
   scp -i $env:USERPROFILE\.ssh\gachon-07-key.pem -r buzz ubuntu@<EC2 퍼블릭 IP>:~/
   ```
2. 서버에 접속해서 키 파일을 만들고 설치 스크립트를 실행한다.
   ```
   ssh -i $env:USERPROFILE\.ssh\gachon-07-key.pem ubuntu@<EC2 퍼블릭 IP>
   cd ~/buzz
   cp .env.example .env && nano .env      # 키 입력 후 Ctrl+O, Enter, Ctrl+X
   bash setup_ec2.sh
   ```
   스크립트가 패키지 설치 → 키워드 1개 시험 → 매일 자동 실행 등록까지 한다.
3. 키워드를 바꿀 때는 서버의 `watchlist.txt`를 고치면 다음 날부터 반영된다.

**직접 등록하려면** — `crontab -e`에 추가. EC2 시계는 기본이 세계 표준시(UTC)라, 한국 시간 오전 6시 10분은 UTC 21시 10분이다:
```
10 21 * * * cd /home/ubuntu/buzz && /usr/bin/python3 collect_buzz.py >> output/cron.log 2>&1
```
(`timedatectl`로 서버 시간대를 확인하고, Asia/Seoul로 바꿨다면 `10 6 * * *`로 쓴다.)

**Windows 작업 스케줄러** — 컴퓨터가 켜져 있어야 한다.
작업 만들기 → 트리거: 매일 06:10 → 동작: 프로그램 `python`, 인수 `collect_buzz.py`, 시작 위치: 이 폴더 경로.

## 알려진 한계
- 큰 유행은 하루 글이 1,000개를 넘어 `blog_capped=1`이 된다. 이 값은 하한값으로만 쓴다.
- 구매 의도 규칙은 임시다. "사봤" 같은 표현이 광고 글에도 들어가므로 비율을 그대로 믿지 말고, 텍스트 분류 모델로 교체할 때 비교 기준(기준선)으로 쓴다.
- 키워드가 흔한 단어면(예: "약과") 유행과 상관없는 글도 섞인다. 필요하면 더 구체적인 표현으로 바꾼다.
