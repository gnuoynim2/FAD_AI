# 과거 검색량 수집 + 반짝 유행 자동 판정

모델 학습에 쓸 **과거 유행 데이터셋**을 만든다.
1. `collect_trend.py`: 네이버 데이터랩에서 2016년부터 주 단위 검색량을 받아, 키워드끼리 비교할 수 있게 맞춘다.
2. `label_fads.py`: 곡선 전체를 보고 반짝 유행 / 트렌드 / 계절 / 진행 중을 자동 판정하고 그래프를 그린다.

## 준비
```bash
pip install -r requirements.txt
cp .env.example .env     # NAVER API HUB 키 입력 (buzz와 같은 키)
```
`keywords.txt`에 키워드를 넣는다. 형식은 `이름 | 같은 뜻의 검색어들 | 분야 | 팀 예상 종류`.
- 같은 뜻의 검색어는 한 그룹으로 합쳐서 센다 (예: `흑당버블티, 흑당 버블티, 흑당밀크티`).
- 팀 예상 종류(fad / trend / seasonal / fizzle)는 자동 판정과 비교해 규칙을 조정하는 데 쓴다.
- **반짝 유행, 오래간 트렌드, 계절 상품, 뜨다 만 것을 섞어서 200개 이상** 모으는 게 목표.

## 실행
```bash
python collect_trend.py --limit 4     # 처음엔 4개만 시험
python collect_trend.py               # 전체 (이미 받은 키워드는 건너뜀)
python label_fads.py                  # 판정 + 그래프
```

## 기준 키워드(anchor)
데이터랩 값은 "그 요청 안의 최댓값 = 100"이라 요청마다 단위가 다르다. 모든 요청에 같은 기준 키워드(기본 `라면`)를 넣고,
키워드 값을 기준 키워드 평균으로 나눠서 **모든 키워드를 같은 단위(기준 키워드 평균 = 1)**로 맞춘다.
- 기준 키워드는 10년 내내 검색량이 꾸준하고 너무 작지 않은 것이 좋다. 바꾸려면 `--anchor`.
- 실행 중 "기준 키워드 평균이 너무 작다"는 경고가 나오면, 그 묶음의 유행 키워드가 너무 커서 기준 키워드 값이 소수점 아래로 뭉개진 것이다. 더 큰 기준 키워드를 고려한다.
- 기준 키워드를 바꾸면 `output/`을 비우고 처음부터 다시 받는다 (섞이면 단위가 달라짐).

## 판정 규칙 (기본값, 옵션으로 조정 가능)
| 항목 | 규칙 | 옵션 |
|---|---|---|
| 정점 | 3주 이동평균이 최고값의 95%에 처음 닿은 주 | `--peak-frac` |
| 시작 | 정점 앞에서 정점의 10% 아래였던 마지막 주의 다음 주 | `--onset` |
| 꺼짐 | 정점의 30% 아래로 떨어진 뒤 8주 연속 아래 | `--decay`, `--hold` |
| seasonal | 장기 추세를 뺀 곡선의 52주 간격 자기상관 ≥ 0.5 | `--season` |
| fad | 정점 후 26주 안에 꺼짐 | `--fad-weeks` |
| trend | 정점 후 52주가 지났고, 40~52주 평균이 정점의 50% 이상 | |
| ongoing | 정점 뒤 기간이 짧아 아직 결말을 모름 (수명 예측에서 "아직 안 꺼짐"으로 사용) | |
| ambiguous | 어디에도 안 맞음 → 그래프 보고 규칙이나 키워드 확인 | |

기준값(30%, 26주 등)은 정해진 정답이 아니다. 팀 예상과 비교해 보고 근거를 정해 보고서에 적는다.

## 결과
- `output/trend_weekly.csv`: 키워드·주별 값 (`ratio` = 요청 안 상대값, `value` = 기준 키워드 단위)
- `output/labels.csv`: 키워드별 판정, 정점 주, 상승 기간(주), 반감 기간(주), 정점→꺼짐(주), 뾰족함(정점 ÷ 시작 전 1년 중앙값), 계절 상관, 팀 예상과 일치 여부
- `output/plots/<키워드>.png`: 전체 기간 + 정점 주변 확대, 시작·정점·절반·꺼짐 표시
- `output/overview.png`: 종류별로 정점 = 1로 맞춘 곡선 겹쳐 보기
